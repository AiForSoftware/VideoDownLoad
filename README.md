# VideoDownLoad · Universal Video Downloader (Windows)

A Windows desktop video downloader: it wraps the command-line download engine `vd` in a
GUI shell (pywebview + Edge WebView2) and supports parsing, quality selection, concurrent
downloading and task-level pause/resume for **Douyin / Bilibili / YouTube / Tencent Video**,
plus **automatic subtitle download and muxing into the video**. The UI ships in
**Chinese and English** (Chinese by default; a language picker is shown on first launch).

## ✨ Features

| Feature | Description |
|---|---|
| Multi-platform parsing | Douyin, Bilibili, YouTube and Tencent Video (`v.qq.com`) parsers; `WebMediaGrabber` as a generic web-media fallback |
| Quality selection | 4K / 1080P+ / 1080P / 720P / 480P … enumerated as separate entries, grouped in the UI |
| Download orchestration | Concurrent downloads (configurable "simultaneous downloads"), task-level **pause / resume / cancel** |
| Subtitle muxing | Subtitle tracks are downloaded and muxed in automatically: Bilibili proprietary JSON→VTT, YouTube captionTracks, HLS (m3u8) auto-extraction |
| Login state | Top-bar "Login" button opens a DrissionPage window; cookies are stored per platform in `per_source_cookies` |
| Self-healing startup | Supervisor + UI child process; a hung WebView2 init is retried (up to 5×) and the frozen attempt is never shown to the user |
| Single instance | Re-opening focuses the existing window and shows a reminder — it never kills a launch in progress |
| Bundled tools | `N_m3u8DL-RE` (HLS/m3u8) and `aria2c` (multi-threaded) ship with the package; ffmpeg/ffprobe come from the system PATH |
| Version management | The version auto-increments on every build (`version.txt` is the single source of truth) and is used for install/activation reporting |
| Multilingual | Chinese / English (Chinese by default). Stored in `config.language` + `localStorage['vd_lang']`; the first launch (`language` empty) shows a one-time picker with the current language highlighted, and the top-bar globe icon switches it anytime |
| Parse-failure guidance | When no valid link is parsed on any platform, one clear prompt says "log in to this platform and retry" (top toast, 5s); the raw error stays available on hover instead of flooding the result card |

## 🏗 Architecture

### Layers

```
┌──────────────────────────────────────────────────────────────┐
│  Frontend UI    app/web/  index.html + app.js + styles.css    │  rendered by Edge WebView2
│                 (3 themes = CSS variable sets; adaptive poll)  │
├──────────────────────────────────────────────────────────────┤
│  Bridge         app/backend/api.py  JsApi                     │  window.pywebview.api.*
│                 ★ every attribute must be `_`-prefixed or      │
│                   pywebview walks the whole object graph and   │
│                   cold-start RSS climbs to several GB          │
├──────────────────────────────────────────────────────────────┤
│  Service        app/backend/core.py  VideoDlService           │  config / job queue /
│                                                               │  lazy engine load / orchestration
├──────────────────────────────────────────────────────────────┤
│  Progress bus   app/backend/progress.py  ProgressBus          │  hijacks rich Progress →
│                                                               │  pause/cancel checkpoints (per job)
├──────────────────────────────────────────────────────────────┤
│  Engine         engine/vd/                                    │  parse / download / subtitles / mux
│                 ├─ vd.py            VideoClient orchestration  │
│                 ├─ modules/sources/ platform parsers (lazy)    │
│                 ├─ modules/grabber.py  WebMediaGrabber         │
│                 ├─ modules/utils/   chromium / youtubeutils …  │
│                 └─ modules/js/       non-python assets (datas) │
├──────────────────────────────────────────────────────────────┤
│  External tools ffmpeg / ffprobe (PATH), N_m3u8DL-RE,          │
│                 aria2c (bundled in bin/), node (optional)      │
└──────────────────────────────────────────────────────────────┘
```

### Process model

```
VideoDLDesktop.exe                     ← supervisor (owns the single-instance lock)
   │  passes the "page loaded" flag-file path via env var
   └── VideoDLDesktop.exe --child      ← UI child process
         starts hidden → writes the flag once loaded → shown via native ShowWindow
         no flag before the timeout → psutil kills the whole subtree → retry (max 5)
```

- The first 2 attempts get 60s (cold start + Defender scan), later ones 30s.
- The liveness probe must fail **twice in a row** before retrying, so a legitimate cold
  start is never killed.
- On window close, `_hard_exit()` recursively kills the process tree — "closed window"
  really means "process gone".

### Data flow (one download)

```
Paste URL
  → JsApi.parse() → VideoDlService.parse()
      → lazy engine: the parser module is matched by hostname
        (the module name must be a substring of the hostname)
      → parser returns a list of VideoInfo (one per quality, with the audio "set of five")
  → pick qualities in the UI → enqueue(): each entry is submitted to the thread pool
    (max_workers = simultaneous downloads)
  → engine downloads (requests / curl_cffi; HLS via N_m3u8DL-RE; m3u8/mpd via ffmpeg)
      → ProgressBus reports progress per (job_id, item_key)
      → pause/cancel raise DownloadPaused / DownloadCancelled at the checkpoints
  → video + audio downloaded separately → ffmpeg mux (copy, then transcode fallback)
  → subtitles: download → convert if needed (Bilibili JSON→VTT) → mux with ffmpeg
  → output written to work_dir; unfinished jobs persist to jobs.json and can be resumed
    after a restart
```

## 🚀 Quick start

### Requirements

- Windows 10 / 11 (x64)
- Python 3.11
- Microsoft Edge WebView2 Runtime
- **ffmpeg / ffprobe** on the system PATH (required for audio+video muxing)
- `N_m3u8DL-RE` and `aria2c` are bundled — no separate install needed

### Run from source

```powershell
cd D:\CodeBuddy\VideoDownLoad
pip install -r requirements.txt      # ★ install yt-dlp too, or audio muxing silently breaks
$env:PYTHONIOENCODING = "utf-8"
python app\app.py
```

### Build

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build_now.ps1
```

Steps: ① bump the version → ② kill running instances → ③ pre-delete `dist`/`build`
→ ④ PyInstaller build → ⑤ print key log lines → ⑥ verify the artifact
(output in `dist/VideoDLDesktop/`).

> Do **not** bypass the script with `python -m PyInstaller build.spec`: the version would
> not be bumped and activation reporting would treat the new build as the same version.

### Headless self-test

```powershell
dist\VideoDLDesktop\VideoDLDesktop.exe --selftest
```

## ⚙️ Configuration

Config file: `C:\Users\<you>\AppData\Local\vd\vd-desktop\config.json`

| Key | Meaning |
|---|---|
| `work_dir` | download output directory |
| `concurrent_downloads` | number of simultaneous downloads (thread pool size) |
| `default_quality` | `best` / `4k` / `1080p` / `720p` / `480p` / `360p` / `auto` |
| `download_subtitles` | download subtitles and mux them into the video |
| `allowed_sources` | list of enabled parser class names |
| `per_source_cookies` | per-platform login state (written by the login dialog) |
| `proxy` | proxy (`host:port`, empty = direct) |
| `language` | UI language: `zh-CN` / `en-US`; empty = not chosen yet (a one-time picker is shown on first launch) |

Diagnostic logs live in the same directory — the first place to look when startup hangs:
- `Logs\startup.log` (process-level events with timing / memory / threads per line)
- `Logs\desktop.log` (engine log)

## ⚠️ Known limitations

- **No HTTP range resume**: resuming re-submits the entry and the engine re-downloads it
  from the beginning.
- ffmpeg / ffprobe / node come from the system PATH; if missing, muxing or JS-based
  parsers will not work.
- YouTube applies **temporary IP throttling** (recovers over hours to days). During that
  window every tool — including yt-dlp and YoutubeDownloader — fails at once. This is a
  network state, not a code defect.
- **Tencent Video**: supports `v.qq.com/x/cover/...` and `/x/page/...`; qualities are
  enumerated from the `fl.fi` list returned by the API (commonly 480P / 720P, depends on
  the title — 1080P is not guaranteed). Single-segment sources only: multi-segment sources
  (`fn` like `a.p201.1.mp4`) are not stitched and fall back to `WebMediaGrabber`.
- Internal engine parse errors can only be surfaced as "please parse again"; the root cause
  lies in the engine's assumptions about site data structures.
